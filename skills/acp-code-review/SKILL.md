# Code Review Skill

评审人类或 AI 编码代理编写的代码。目标是发现行为变更、风险、缺失的验证和不必要的复杂性。

---

## 评审心态

评审 diff，而非总结。代理的解释可能有帮助，但不是证据。

证据存在于：
- diff
- 测试
- 构建输出
- 运行时行为
- 日志
- 产品需求

---

## 评审工作流程

### 1. 理解预期变更

识别：
- 此变更试图解决什么问题？
- 什么行为应该改变？
- 什么行为应该保持不变？
- 哪些用户或系统受影响？

若意图不清，批准前先问。

### 2. 追踪每个有意义的 Diff

对每个有意义的变更块，问：

> 为什么此变更是达到声明目标所必需的？

当 diff 很大时，优先直接读取实际的 `git diff` 输出，而非依赖 PR 描述。对于跨文件影响（如重命名的函数），使用 Explore 子代理查找调用点。

标记的变更：
- 与任务无关
- 纯格式化噪音
- 意外的行为变更
- 机会主义清理
- 提前抽象

### 3. 检查行为和边缘情况

查找：
- 空值或空值
- 错误处理
- 重试行为
- 竞态条件
- 向后兼容性
- 性能影响
- 安全影响
- 数据丢失风险

### 4. 检查验证

若无验证证据，PR 较弱。查找：
- 单元测试
- 集成测试
- 类型检查
- Lint
- 构建结果
- 手动测试笔记

若验证缺失，要求提供。

### 5. 决定评审结果

使用以下结果之一：
- Approve：变更小、意图清晰、验证充分
- Comment：次要问题或问题
- Request changes：行为风险、缺失验证、无关变更或意图不清

## AI 生成代码警告信号

当 diff 包含以下内容时格外小心：
- 大规模无关重写
- 小任务的新抽象
- 仅有一个调用者的通用辅助函数
- 无迁移的重命名 API
- 仅验证实现细节的测试
- 描述明显代码的注释
- 无检查的自信总结

---

## 深度评审维度（需彻底审计时）

### 1. 缺陷或副作用
- 空指针/零值风险
- 数组/索引越界
- 并发问题（竞态条件、死锁）
- 资源泄漏（DB 连接、文件句柄）
- 异常处理缺口
- 业务逻辑错误
- 缺失权限检查
- 缺失输入验证

### 2. 性能问题
- N+1 查询问题
- 循环中的外部 API 调用
- 全表扫描/缺失索引
- 内存泄漏
- 算法复杂度问题
- 不必要的同步操作
- 连接池配置错误

### 3. 代码质量问题
- 命名不清
- 缺失注释
- 代码重复（DRY 违规）
- 方法过长/职责不清
- 硬编码配置
- 未使用代码或导入

### 4. 最佳实践违规
- 设计模式误用
- SOLID 原则违规
- 安全问题（SQL 注入、XSS、CSRF）
- 事务边界问题
- 不一致的错误码
- 测试覆盖不足
